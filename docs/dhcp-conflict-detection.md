# 冲突检测：不发出别人已经在用的地址

lessor 做两件事来避免把网段搞乱：

1. **不发已被静态占用的地址** —— 后台持续探测地址池，被占的记下来，分配时绕开。
2. **发现同网段已有 DHCP 服务器就告警** —— 尤其是旁挂在 MAAS 装机网段上时。

两件事都不阻塞握手，也都不需要特权。下面记的是做的时候踩到的坑。

## 探测为什么不能放在握手路径上

直觉做法是"选中一个地址 → ARP 探一下 → 没人应答再 OFFER"。这条路走不通：

- 一次 ARP 往返要几百毫秒。DHCP 客户端（尤其是 PXE 固件）等不起，
  批量装机时几十台机器同时握手会把这个延迟叠起来。
- 探测失败不该让客户端拿不到地址。把探测放在关键路径上，就等于让一个
  尽力而为的检查有权否决整个分配。

所以做法是：后台任务持续扫描地址池、结果进内存缓存（TTL 5 分钟），
分配路径只查缓存 —— 纳秒级，不做任何 IO。

代价是**服务刚起来的头几秒缓存是空的**，那时按"没冲突"放行。
接受这个代价的理由：静态占用本来就该在网段规划时避免，为了这几秒
让每个客户端多等半秒不划算。首轮扫描安排在启动后 3 秒（而不是等满一个
60 秒周期），把这个盲区压到最小。

探测手段复用了设备发现那一套：发 UDP 逼系统自己做 ARP，再读邻居表。
不需要 raw socket，三个平台通用，也不需要特权。

**探不到 ≠ 地址空闲。** 设备可能关着机。所以结果只当作"已知被占"的
黑名单用，不能反过来当成"未列出即可用"的证明。

## 坑：探测别人的 DHCP 必须绑 68 端口

这是 [pxe-source-port.md](pxe-source-port.md) 那个坑的镜像面。

检测同网段其他 DHCP 服务器的做法是：以客户端身份广播一个 DISCOVER，
看有没有人应答。第一版这么写：

```rust
let sock = UdpSocket::bind((bind, 0)).await?;   // 临时端口
sock.send_to(&probe, ("255.255.255.255", 67)).await?;
```

在真实网段上（MAAS 在 192.168.73.11 发地址）实测：**一个应答都收不到**，
于是稳定地报"本网段没有其他 DHCP 服务器"。

原因：**DHCP 服务器把应答发给客户端端口 68，完全不看请求是从哪个端口来的。**
绑临时端口，应答就落到 68 上，我们的 socket 永远收不到。

同一个 DISCOVER、同一个 MAAS，只改绑定端口：

| 绑定端口 | 收到的应答 |
| --- | --- |
| 68 | 1 个 OFFER（`from=192.168.73.11:67`，`server-id=192.168.73.11`） |
| 临时端口（63702） | 0 个 |

这个 bug 特别值得记，因为**它的失败形态是"一切正常"**：日志里没有告警，
人会理解成"查过了，没冲突"。一条安全检查给出假的全清信号，比不做这条检查更糟 ——
不做至少不会让人放心。

所以除了绑对端口，还有一条：**绑不上时必须如实说"没查成"**，
不能返回空列表了事。代码里这条路径返回 `Err`，调用方打的是
"同网段 DHCP 检查没能进行"，而不是"未发现其他 DHCP 服务器"。

两个连带的细节：

- 68 端口上通常已经有系统自己的 DHCP 客户端占着，必须设 `SO_REUSEADDR`，
  否则绑不上，检查同样做不成。
- 探测用的端口对固定是 67/68，**不跟随 `--dhcp-port`**。我们探的是别人家的
  服务器，它们守在标准端口上，跟我们自己听哪儿没关系。

## 池满时要说清是谁占着

"地址池已耗尽"这句话没法排查。真实场景里池满经常不是因为客户端太多，
而是因为**一批地址被静态占用挡掉了** —— 那是配置问题，不是容量问题。

所以探测记录里连 MAC 一起存，池满的事件带上占用者：

```
地址池已耗尽（探测到 6 个地址被静态占用：
  192.168.73.5 被 00:0c:29:a6:e5:83 占用、
  192.168.73.11 被 00:0c:29:08:79:6d 占用、
  192.168.73.21 被 00:0c:29:ea:43:12 占用 等）
```

看到这句就知道该去查网段规划，而不是去扩池子。

## 实测

实验网段 192.168.73.0/24，上面跑着 MAAS（.11）和几台节点 VM。
把 lessord 的 DHCP 监听挪到高位端口（`--dhcp-port 6767`）跑，
这样不会干扰段上的真实客户端，而 ARP 探测和"找其他 DHCP"走各自独立的
路径，行为仍然是真的。

配置：`--listen 192.168.73.1 --pool 192.168.73.5-192.168.73.24`（20 个地址）。
段上实际存活 6 台：`.5 .11 .21 .22 .23 .24`。

**其他 DHCP 服务器**：启动后 0.94 秒告警，点名 192.168.73.11。

```
WARN 同网段检测到其他 DHCP 服务器 —— 两边同时发地址会打架 server=192.168.73.11
WARN 本网段已有其他 DHCP 服务器。两边同时发地址会互相干扰 —— 确认这是你要的，
     否则请停掉其中一边 servers=[192.168.73.11]
```

**已占地址不被 OFFER**：连发 22 个不同 MAC 的 DISCOVER，拿到的地址是

```
.6 .7 .8 .9 .10 .12 .13 .14 .15 .16 .17 .18 .19 .20     （14 个）
```

被跳过的正好是那 6 台存活主机的地址，不多不少；剩下 8 次请求无应答
（20 − 6 = 14 个可用地址发完后池满）。事件里的占用者 MAC 与系统邻居表逐个对得上。

## 关掉它

`--no-probe` 关掉地址占用探测。留这个开关是给那些禁止主动探测的网络 ——
有些安全策略会把 ARP 扫描当告警。正常部署不该关：探测不需要特权，
也不在握手路径上。
