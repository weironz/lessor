# 跨网段：DHCP 中继

**DHCP 的首次交互是二层广播，路由器不转发。** 客户端还没有 IP，只能发
`255.255.255.255`。所以默认情况下，DHCP 服务器必须和客户端在同一个二层。

跨网段的标准解法是**中继代理**（交换机 / 路由器上的 `ip helper-address`）。
企业里多网段 DHCP 基本都是这么跑的。

## 一次中继握手长什么样

```
客户端                    网关（中继）                     lessord
  │                          │                              │
  │ DISCOVER 广播 ─────────► │                              │
  │                          │ giaddr = 网关在客户端网段的地址 │
  │                          │ 单播 ─────────────────────►  │
  │                          │                              │ 按 giaddr 选作用域
  │                          │                              │ 从那个网段的池里分
  │                          │ ◄──── 单播回 giaddr:67 ────── │
  │ ◄──── 放回线上 ───────── │                              │
```

三件事值得单独记住：

1. **`giaddr` 是网关在客户端那个网段上的地址**，不是网关的任意一个地址。
   服务器完全靠它判断客户端在哪个网段。
2. **应答单播回 `giaddr` 的 67 端口**（不是客户端端口 68）—— 中继是以
   服务器身份收这个包的。
3. **续租不走中继。** 客户端拿到地址之后，RENEW 是直接单播给服务器的，
   报文里**没有 `giaddr`，只有 `ciaddr`**。这一条最容易漏，后面细说。

## 怎么配

被中继的网段本机上没有任何地址，所以要显式标 `viaRelay`：

```json
{
  "listeners": [
    { "serverIp": "192.168.10.5" }
  ],
  "scopes": [
    {
      "id": 1, "name": "机房本段", "enabled": true,
      "subnet": "192.168.10.0", "prefix": 24,
      "pools": [{ "start": "192.168.10.100", "end": "192.168.10.200" }],
      "exclusions": [], "reservations": [],
      "leaseSecs": 3600, "offerSecs": 30, "declineQuarantineSecs": 3600
    },
    {
      "id": 2, "name": "BMC 段（经中继）", "enabled": true,
      "subnet": "10.20.30.0", "prefix": 24,
      "viaRelay": true,
      "pools": [{ "start": "10.20.30.100", "end": "10.20.30.200" }],
      "exclusions": [], "reservations": [],
      "router": "10.20.30.1",
      "leaseSecs": 3600, "offerSecs": 30, "declineQuarantineSecs": 3600
    }
  ]
}
```

要点：

- **`viaRelay` 必须显式标**。不标的话配置校验会拒绝，报"没有对应的监听器"。
  这个校验是对的 —— 忘配监听器是最常见的配置错误，不能因为要支持中继就
  一刀切放开。
- **仍然需要至少一个监听器。** `viaRelay` 免掉的是"这个网段要有本机地址"，
  不是"不用有人收包"。中继会把报文单播到某个监听器上。
- 路由器那侧配 `ip helper-address <lessord 的地址>`（各家叫法不同，
  华为/华三是 `dhcp select relay` + `dhcp relay server-select`）。
- 被中继网段的 `router` 要自己填 —— 那是客户端的网关，不是 lessord。

## 下发的 option 54 是谁

**是收包那个监听器的地址**（上例里是 `192.168.10.5`），不是 `giaddr`。

客户端拿它做两件事：认出是哪个服务器给的地址（多服务器时用来选），
以及续租时往哪儿单播。所以它必须是一个**客户端路由可达**的地址 ——
既然中继能把包送到我们这儿，反向也就是通的。

## 坑：续租不经过中继

这是实现时真出过问题的地方，值得单独说。

客户端进入 RENEWING 状态后，是**直接单播给服务器**的：目标是 option 54
给的那个地址，报文里 `ciaddr` 填自己当前的地址，**`giaddr` 为空**
（中继根本不在这条路径上）。

于是"用 `giaddr` 判断网段，没有就用收包网卡的地址"这个写法在这里会出错：
收包网卡在**另一个**网段里，选出来的是错的作用域，接着因为
"请求的地址不属于本子网"回一个 NAK —— **一个正在正常工作的客户端被迫
丢掉租约重来**。网段越大，这个错越密集。

正确的判断顺序是三层：

| 线索 | 什么时候有 |
| --- | --- |
| `giaddr` | 经中继转发来的报文 |
| `ciaddr` | 客户端已经持有地址 —— **续租时只有这一条** |
| 收包监听器的本机地址 | 直连的常规情况 |

回归测试 `renewal_from_a_relayed_client_finds_its_own_scope` 钉住这条：
去掉 `ciaddr` 那一层，它会立刻失败在"不能 NAK 一个有效的租约"。

## 实测

lessord 只在 `192.168.73.1` 上有监听器，配一个 `192.168.233.0/24`
的 `viaRelay` 作用域（本机在这个网段上没有任何地址）。用脚本模拟中继，
从 `192.168.233.1:6767` 发 `giaddr=192.168.233.1` 的报文：

```
DISCOVER -> 应答类型=2 yiaddr=192.168.233.150 giaddr=192.168.233.1 server-id=192.168.73.1
   来自 ('192.168.73.1', 6767)
   掩码=255.255.255.0 网关=192.168.233.1 DNS=223.5.5.5
REQUEST  -> 应答类型=5 yiaddr=192.168.233.150 giaddr=192.168.233.1
```

地址来自被中继网段的池、掩码/网关/DNS 取自那个作用域、server-id 是收包
监听器、`giaddr` 原样带回、应答单播回中继的服务端口。

续租（`ciaddr=192.168.233.150`、无 `giaddr`）单独发一发，服务端日志：

```
已应答 client=ac:1f:6b:8e:00:42 request=REQUEST reply=ACK ip=192.168.233.150
```

是 ACK 而不是 NAK，作用域选对了。

## option 82 必须原样带回

RFC 3046 §2.2 是 MUST：**应答里必须原样带回收到的 option 82**（中继代理信息）。

交换机在转发时把"客户端接在哪个物理端口"塞进这个选项（circuit-id / remote-id），
应答回来时靠它把包送回那个端口。不带回去，有的中继代理直接把应答丢掉。

这个 bug 的现象特别容易误判：**服务端日志一行行"已应答"，客户端一个都收不到**。
而且只在真交换机上出现 —— 实验室里两台机器对着打是复现不出来的，因为没有
中继代理去检查这个选项。

lessor 把它当不透明字节原样搬运，不解释也不修改 —— 那是中继和它自己之间的
约定。NAK 也一样要带（客户端换网段后拿到的正是 NAK，那一条送不回去它会一直
重试到超时）。

三条测试钉住：正常应答带回、NAK 也带回、没有中继时不凭空造一个。

## 顺带一提：中继也是一个跨三层的抓包点

`--observe` 只收不答。在路由器上**多加一个** helper-address 指向一个
`--observe` 的 lessord，就能收到那个网段每个 DHCP 请求的副本，而一个
字节都不会发出去 —— 不需要在目标网段上找机器，也不会和现有的 DHCP 抢答。

给真机 BMC 取报文（ROADMAP 的 M9a）走这条最省事，代价是要动路由器配置。
