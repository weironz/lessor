# 现场 runbook

带一台笔记本去机房，给一批还没装系统的机器发地址。从插网线到走人。

面向的是**现场那个人**，不是开发者。每一步都写清楚"看到什么算成了"，
以及"没看到该怎么办" —— 现场没有第二个人可问。

## 你需要什么

- 一台 Windows 笔记本（**不需要管理员权限**）
- 一根网线，或一个 USB 网卡
- `lessor` 安装包（桌面端）或 `lessord.exe`（命令行）

不需要：管理员账号、关防火墙、装 .NET/Python/WSL、连外网。

## 走一遍

### 1. 插线，确认本机拿到了目标网段的地址

装机网段一般没有 DHCP（那正是你来的原因），所以笔记本多半拿不到地址，
需要手工配一个。**这一步需要管理员权限**，是整个流程里唯一需要的地方。

```powershell
Get-NetIPAddress -AddressFamily IPv4
```

要在输出里看到一个落在目标网段里的地址，比如 `192.168.88.1`。
没有的话手工配（管理员）：

```powershell
New-NetIPAddress -InterfaceAlias "以太网 2" -IPAddress 192.168.88.1 -PrefixLength 24
```

> 随包的 `lessor-netcfg` 也能做这件事，它会把"需要管理员"这件事说清楚，
> 而不是给你一个 5 号错误码。

### 2. 起服务

桌面端：双击，进界面，选网卡，点"开始发地址"。

命令行：

```bash
lessord.exe --listen 192.168.88.1 --pool 192.168.88.100-192.168.88.200 --open
```

`--open` 会自动打开浏览器。看到 `开始监听 server_ip=192.168.88.1` 就是起来了。

**起不来**：报错里会写原因。最常见的是端口被占（`Internet Connection Sharing`、
VMware DHCP、另一个 DHCP 工具），提示里带了排查命令，照着敲。

### 3. 确认在发地址

界面上"实时报文"页会滚出 `DISCOVER → OFFER → REQUEST → ACK`。
"租约"页出现机器，就成了。

**一分钟过去了一条都没有**：界面顶部会自己弹出一条黄色提示，
展开有按可能性排好序的排查清单。第一条几乎总是防火墙 ——
Windows 默认拦掉未放行程序的入站 UDP：

```powershell
New-NetFirewallRule -DisplayName lessord -Direction Inbound -Protocol UDP -LocalPort 67 -Action Allow
```

（需要管理员。这是第二个、也是最后一个需要管理员的地方。）

### 4. 走人

- 装完就走：起服务时加 `--idle-exit 600`，十分钟没有请求它自己退出。
- 要留着长期跑：`lessord --install-service --listen ... --pool ...`
  注册成系统服务，开机自启、崩溃自拉起（**这一步需要管理员**）。
  同时加上 `--config` 和 `--lease-db`，否则重启后配置和租约都没了。
- 前台跑着的：Ctrl-C。没反应就再按一次，第二次会立即结束。

## 现场会遇到的情况

### 网卡被拔了 / USB 网卡松了

lessord 不会死，也不会继续拿一个已经失效的地址去应答（那会让客户端
拿到租约却续不上，比直接停掉更糟）。日志和界面上会看到：

```
本机上找不到这个地址了（网卡被拔掉或被禁用？）—— 停止应答，等它回来
```

插回去，最多 3 秒后自动恢复：

```
地址回来了，重新开始监听
```

不用重启服务。

### 这个网段已经有别的 DHCP 了

启动时就会告警并点名对方地址：

```
本网段已有其他 DHCP 服务器。两边同时发地址会互相干扰 —— 确认这是你要的，
否则请停掉其中一边 servers=[192.168.88.5]
```

**这是让你做决定，不是替你做决定。** 两个 DHCP 同时发地址，机器可能装到
一半失联。要么停掉一边，要么确认它们的地址池不重叠。

### 地址池说耗尽了，但机器没那么多

多半是池里一批地址被已经在用静态 IP 的机器占着。lessord 会在事件里点名：

```
地址池已耗尽（探测到 6 个地址被静态占用：192.168.88.105 被 00:0c:29:a6:e5:83 占用 …）
```

这是网段规划问题，不是容量问题 —— 把池子挪开那些地址，别急着扩池。

### 要给 PXE / 网络引导用

加 `--boot-file` / `--next-server`。三类引导客户端（PXE 固件、UEFI HTTP Boot、
iPXE）各有各的参数和坑，见 [pxe-client-identification.md](pxe-client-identification.md)
和 [debugging-pxe.md](debugging-pxe.md)。

### 要把某台机器钉死到固定地址

界面上"作用域 → 静态保留"，填 MAC 和地址。加保留时会顶掉压在该地址上的
他人动态租约，不用先去撤租约。

## 远程做这件事（Tailscale / VPN）

**DHCP 过不去三层。** 它靠广播工作，而 Tailscale 和多数 VPN 都是三层隧道，
广播不会转发过去。所以**不能**在自己电脑上跑 lessord 去给远端机房的 BMC
发地址 —— 这条路根本不通，不是配置问题。

可行的是把 lessord 放进机房里：

1. 在机房找一台机器，它得有一块网卡**和 BMC 在同一个二层/VLAN** 上。
2. 在那台机器上跑 lessord，管理接口开给内网：

   ```bash
   lessord --listen <那台机器在BMC网段上的地址> --pool ... \
           --http 0.0.0.0:8080 --token <一个口令>
   ```

   `--token` 不是可选的 —— 管理接口一旦不只听 127.0.0.1，就必须有鉴权。
3. 从 Tailscale 连过去开 `http://<机房机器>:8080`。

容器部署要 `--network host`。桥接网络下广播出不去，NAT 也过不来，
`docker run -p 67:67/udp` 是不够的。

### 网段上已经有 DHCP 的话，先只看不答

生产机房的 BMC 网段十有八九已经有 DHCP 在跑。这时候直接起 lessord 就是
两个 DHCP 抢答，机器可能装到一半失联。取证阶段用只看不答：

```bash
lessord --listen <地址> --pool <随便一段没人用的> --observe --capture bmc.jsonl
```

它会收包、记录、在界面上显示"本来会怎么答"，但**一个字节都不往网络上发**。
跑上一阵子（等有机器重启或者续租），把 `bmc.jsonl` 拿走。

那个文件里是每个报文的原始字节。离线重放：

```bash
lessord --replay bmc.jsonl --listen 192.168.88.1 --pool 192.168.88.100-192.168.88.200
```

走的是真正的决策层，逐条打印我们会怎么处理，无法解码的单独列出来带原始字节 ——
那些就是要动手的地方。

## 需要管理员的地方，一共三处

其余全程普通用户即可 —— 这是刻意的设计，见
[README 的"不需要特权"](../README.md#不需要特权)。

| 什么事 | 什么时候需要 |
| --- | --- |
| 给网卡配静态地址 | 目标网段没有 DHCP 时（通常都需要） |
| 放行防火墙入站 UDP 67 | 只在收不到请求时 |
| 注册成系统服务 | 只在要长期常驻时 |

**跑 lessord 本身不需要管理员**，Windows 上绑 67 端口不需要提权
（"低端口需特权"是 Unix 的约定）。看到"需要管理员"的提示时，
先看清楚它说的是上面哪一件事。
